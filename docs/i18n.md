# Texts and languages

Two separate things have a language: the widget's own texts (buttons, labels, statuses), which
`@elicitor/react-ui` owns, and the assistant's messages, which the model writes. The provider's
`locale` drives both.

## Built-in bundles

`@elicitor/react-ui` ships complete bundles for English (`en`), Estonian (`et`), Finnish (`fi`) and
Russian (`ru`). Each has exactly the 57 keys listed below.

```tsx
<ElicitorProvider transport={transport} locale="fi">
```

- `locale` is normalised by its first subtag: `"et-EE"` and `"ET"` use `et`. A locale without a
  bundle uses `en`.
- Dates use `Intl.DateTimeFormat` with the locale as given (medium date style), so `"de-DE"` gets
  German dates even though the texts fall back to English.
- `locale` is also sent as `context.language`. Core tells the model to write in that language,
  using its English name from a table: `en`, `et`, `fi` and `ru` by default (`DEFAULT_LANGUAGES`),
  anything else falls back to `defaultLanguage` (`"en"`).

## Overriding single keys

The provider's `messages` prop replaces individual keys of the selected bundle. Unknown keys and
empty strings are ignored.

```tsx
<ElicitorProvider transport={transport} locale="et" messages={{ report: "Leidsid vea?" }}>
```

`messages` accepts a full bundle (`Messages`), a partial one (`Partial<Messages>`,
`MessageOverrides`) or a plain `Record<string, string>`, without a cast. Type the overrides with
`MessageOverrides` to catch misspelt keys:

```ts
import type { MessageOverrides } from "@elicitor/react-ui";

const texts: MessageOverrides = { report: "Send feedback", list: "My feedback" };
```

Placeholders in `{braces}` are filled by the widget: `reportNumber` gets `{number}`, `sentBody`
gets `{list}` (the `list` text). Keep them in your overrides.

## Adding a language

There is no bundle registry. For a language without a bundle, pass all 57 keys as `messages`.
Typing the object as `Messages` makes the compiler require every key.

```ts
import { bundles, type Messages } from "@elicitor/react-ui";

const de: Messages = {
  ...bundles.en, // start from English, then translate every key
  report: "Problem melden",
  list: "Meine Meldungen",
  // ...
};

// <ElicitorProvider transport={transport} locale="de" messages={de}>
```

On the server, tell core the language's name and, optionally, the note shown when the assistant is
unavailable:

```ts
import { createIntake, DEFAULT_LANGUAGES } from "@elicitor/core";

const intake = createIntake({
  model,
  store,
  prompt,
  languages: { ...DEFAULT_LANGUAGES, de: "German" },
  unavailableNotes: {
    de: "Der Assistent ist gerade nicht verfügbar. Die Meldung wurde so weitergeleitet, wie du sie geschrieben hast.",
  },
});
```

The fake model has scripts for `en`, `et`, `fi` and `ru` only and answers in English otherwise.
Bundles for more languages are welcome as pull requests: add one object to
`packages/react-ui/src/i18n.ts` with every key, and the unavailable note to
`DEFAULT_UNAVAILABLE_NOTES` in core.

## The region-select overlay with your own trigger

The overlay's three texts (hint, whole-view button, cancel) come from the `mark`, `whole` and
`cancel` keys. `<Elicitor />` passes them for you, including to a function trigger's `open()`. When
you open the flow yourself, pass them explicitly, or the overlay shows its English defaults:

```tsx
import { useElicitor, useMessages } from "@elicitor/react-ui";

function ReportMenuItem() {
  const { open } = useElicitor();
  const { overlayLabels } = useMessages();
  return (
    <button type="button" onClick={() => void open({ labels: overlayLabels })}>
      Report a problem
    </button>
  );
}
```

The same `labels` option exists on `useCapture().start()`, and as `capture.labels` on the provider.

## Helpers

`useMessages()` (inside the provider) returns `locale`, the resolved `messages`, `t(key, values?)`,
`status(status)`, `kind(kind)`, `date(iso)` and `overlayLabels`. Outside React:
`resolveMessages(locale, overrides)`, `normalizeLocale(locale)`, `formatMessage(template, values)`
and `bundles`.
